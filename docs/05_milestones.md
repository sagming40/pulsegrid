## 3. 마일스톤 상세

### M0. 환경 구성 ✅ 완료

| 항목 | 내용 |
|---|---|
| 작업 | LibreHardwareMonitor 설치, PawnIO 드라이버 설치, Remote Web Server 활성화 |
| 대상 | 데스크탑, 노트북 양쪽 |
| **완료 기준** | 두 기기 모두 `http://localhost:8085/data.json` 접속 시 센서 JSON 정상 출력 |
| 확인 결과 | 데스크탑(9600X / RTX 5070), 노트북(i7-1255U / Iris Xe) 모두 확인 완료 |

---

### M1. 수집기 프로토타입

| 항목 | 내용 |
|---|---|
| 목표 | LibreHardwareMonitor JSON에서 필요한 값만 추출 |
| 주요 작업 | 1. `requests`로 JSON 요청<br>2. 중첩된 트리 구조 재귀 탐색 함수 구현<br>3. CPU / GPU / RAM 값 추출<br>4. API 명세서 형식(`MetricPayload`)으로 변환 |
| 기술 요소 | Python, `requests`, 재귀 함수, 딕셔너리 다루기 |
| **완료 기준** | 터미널에서 실행 시, API 명세서 2.1절 형식의 JSON이 2초마다 출력됨 |
| 리스크 | 센서 이름이 기기마다 미묘하게 다를 수 있음 → 매핑 테이블로 흡수 |

---

### M2. 서버 + 단일 기기 연동

| 항목 | 내용 |
|---|---|
| 목표 | 데스크탑 1대의 데이터가 웹 브라우저에 실시간 표시 |
| 주요 작업 | 1. FastAPI 서버 기본 구조<br>2. `POST /api/v1/metrics` 구현<br>3. 메모리에 최신 상태 보관<br>4. `WS /ws/dashboard` 구현 (브로드캐스트)<br>5. 최소 HTML 페이지 (숫자만 표시) |
| 기술 요소 | FastAPI, Pydantic 모델, WebSocket, 비동기(async) |
| **완료 기준** | 수집기 실행 → 브라우저 화면의 CPU 사용률 숫자가 2초마다 자동 갱신됨 |
| 리스크 | `async` 개념이 처음이라 학습 시간 필요 → 이 단계에 여유 배분 |

---

### M3. 다중 기기 연동

| 항목 | 내용 |
|---|---|
| 목표 | 노트북까지 붙여서 2대 동시 모니터링 |
| 주요 작업 | 1. 수집기에 설정 파일 분리 (`device_id`, 서버 주소)<br>2. 노트북에서 동일 코드 실행<br>3. 서버 측 기기별 상태 관리 (딕셔너리)<br>4. `status` (online/offline) 판정 로직 |
| **완료 기준** | 두 기기의 데이터가 한 화면에 구분되어 표시되고, 노트북 종료 시 10초 내 `offline` 표시로 전환됨 |
| 리스크 | 노트북의 서버 접속 주소(로컬 IP) 확인 필요 → 공유기 환경에서 테스트 |

## 4. 진행 순서 및 의존 관계

```
M0 ──▶ M1 ──▶ M2 ──▶ M3 ──▶ M4  ═══▶ v1.0 릴리즈 완료                          
                             │
                             ├──▶ M5 (히스토리)
                             ├──▶ M6 (확장 지표)
                             └──▶ M7 (문서화)
```

- M1 ~ M4는 **순차 진행 필수** (앞 단계 없이 다음 단계 불가)
- M5 ~ M7은 v1.0 이후 **독립적으로 진행 가능** (순서 자유)

## 5. 리스크 관리

| 리스크 | 영향 | 대응 |
|---|---|---|
| `async`/WebSocket 개념 학습 지연 | M2 지연 | M2에 여유 시간 배분, 동기 방식 폴링으로 임시 대체 후 개선 |
| 학사 일정(시험/과제) 겹침 | 전체 지연 | P1 항목(M5~M7)을 먼저 축소, P0 완주 우선 |
| 기기별 센서 이름 불일치 | M1 지연 | 센서 매핑 테이블을 설정 파일로 분리해 코드 수정 없이 대응 |
| 범위 확대 유혹 (기능 추가) | 완주 실패 | 요구사항 정의서의 "범위 외 항목" 기준 엄수 |

## 6. 완료 정의 (Definition of Done)

각 마일스톤은 아래 조건을 **모두** 충족해야 완료로 간주한다.

1. 해당 단계의 완료 기준이 실제로 동작함
2. 코드가 Git에 커밋되어 있음
3. 다음 단계를 진행할 수 있는 상태로 정리됨 (임시 코드 제거)
