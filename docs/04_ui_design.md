### 2.1 영역 구성

| 영역 | 구성 요소 | 데이터 출처 |
|---|---|---|
| 헤더 | 서비스명, 연결 기기 수, WebSocket 연결 상태 | WS 연결 상태 + `snapshot` |
| 기기 카드 그리드 | 기기별 카드 (반응형, 화면 폭에 따라 1~N열) | `snapshot`, `metric_update` |
| 추이 그래프 | 최근 60초간 CPU 사용률 추이 (기기별 선) | 클라이언트가 수신 데이터를 누적 |

## 3. 기기 카드 상세 규격

### 3.1 구성 요소

| 요소 | 내용 | 비고 |
|---|---|---|
| 기기 아이콘 | 데스크탑 / 노트북 구분 | `device_id` 기준 |
| 표시 이름 | 사용자 지정 별칭 (예: "데스크탑") | 설정 파일 지정 |
| 호스트명 | `device_name` (예: `DESKTOP-5VSB06S`) | API 필드 그대로 |
| 상태 배지 | `online` / `offline` | `status` 필드 |
| 지표 행 | CPU / GPU / RAM (P0) | 사용률 + 온도 + 게이지 바 |
| 하단 요약 | 디스크 / 배터리 (P1) | 게이지 없이 텍스트만 |

### 3.2 지표 행 표시 형식

```
[항목명]        [사용률]  ·  [온도]
[━━━━━━━░░░░░░░░░░░]   ← 사용률 게이지 바
```

- 사용률: 소수점 1자리 (`19.7%`)
- 온도: 정수 (`68°C`)
- 게이지 바 너비 = 사용률 값 (%)

### 3.3 null 값 처리

API 명세서 2.2절의 `null` 원칙에 따라, 값이 없는 항목은 **행을 숨기지 않고 `—`(대시) 로 표시**한다.

| 상황 | 표시 |
|---|---|
| 노트북 GPU 온도 (센서 없음) | `1.1% · —` |
| 데스크탑 배터리 (기기에 없음) | `배터리 —` (흐린 색) |

> 이유: 행이 사라졌다 나타나면 카드 높이가 계속 변해 화면이 흔들린다. 자리는 유지하고 값만 대시로 표기한다.

## 4. 상태 표시 규칙

### 4.1 온도 경고 임계치

| 구간 | CPU / GPU 온도 | 표시 색상 |
|---|---|---|
| 정상 | ~ 69°C | 기본 (회색) |
| 주의 | 70 ~ 84°C | 노랑 계열 |
| 위험 | 85°C ~ | 빨강 계열 |

### 4.2 사용률 게이지 색상

| 구간 | 사용률 | 색상 |
|---|---|---|
| 정상 | ~ 74% | 파랑 계열 |
| 주의 | 75 ~ 89% | 노랑 계열 |
| 위험 | 90% ~ | 빨강 계열 |

### 4.3 오프라인 상태

`status: offline` 수신 시:
- 카드 전체 투명도 낮춤 (dimmed)
- 상태 배지를 회색 `offline` 로 변경
- 마지막 수신 시각 표시 (예: "2분 전 마지막 수신")
- 지표 값은 마지막 값을 그대로 유지 (빈 화면 방지)

### 4.4 WebSocket 연결 끊김

브라우저와 서버 사이 연결이 끊긴 경우 (서버 다운 등):
- 헤더 상태 표시를 "연결 끊김"으로 변경
- 자동 재연결 시도 (3초 간격)

## 5. 추이 그래프 규격

| 항목 | 값 |
|---|---|
| 표시 지표 | CPU 사용률 (1차 릴리즈 기준) |
| 표시 구간 | 최근 60초 (2초 간격 × 30포인트) |
| 선 구분 | 기기별 색상 (범례 표시) |
| Y축 | 0 ~ 100% 고정 |
| 데이터 관리 | 클라이언트 메모리에 최근 30개만 유지 (오래된 것부터 제거) |

> 1차에서는 서버 히스토리 조회 없이, 브라우저가 실시간 수신한 값만 누적해 그린다. 새로고침 시 그래프는 초기화된다. (히스토리 기반 그래프는 P1)

## 6. 반응형 대응

| 화면 폭 | 카드 배치 |
|---|---|
| 900px 이상 | 2열 (데스크탑/노트북 나란히) |
| 600 ~ 899px | 2열 축소 또는 1열 |
| 600px 미만 (모바일) | 1열 세로 스택 |

- CSS Grid `auto-fit` + `minmax()` 로 자동 처리, 별도 미디어쿼리 최소화
- 모바일에서도 게이지 바와 숫자는 동일하게 표시

## 7. 화면 흐름 (초기 로딩)

```
1. 페이지 접속
       ↓
2. GET /api/v1/devices 호출 → 초기 카드 렌더링
       ↓
3. WS /ws/dashboard 연결
       ↓
4. snapshot 수신 → 카드 갱신
       ↓
5. metric_update 수신 (2초마다) → 카드 값 + 그래프 갱신 (반복)
       ↓
   device_status 수신 시 → 해당 카드 온/오프라인 상태 전환
```
