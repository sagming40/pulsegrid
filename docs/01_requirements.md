# PulseGrid — 요구사항 정의서

> 여러 대의 PC(데스크탑 + 노트북)를 실시간으로 모니터링하는 웹 대시보드

- **작성일**: 2026-07-28
- **작성자**: 사공민규
- **버전**: v0.1 (초안)

---

## 1. 프로젝트 개요

### 1.1 배경
공공데이터(수도권 전철 혼잡도) 분석 프로젝트에서 사용한 pandas 기반 데이터 파이프라인 학습 이후, 이를 응용할 개인 프로젝트로 시작. PC 하드웨어에 대한 평소 관심을 살려, 보유 중인 2대의 기기(데스크탑/노트북)의 하드웨어 상태를 실시간으로 확인할 수 있는 대시보드를 구축한다.

### 1.2 목적
- 여러 대의 이기종(異機種) PC 하드웨어 상태를 한 화면에서 실시간으로 확인
- 백엔드(FastAPI) + 프론트엔드(웹 대시보드) + 실시간 통신(WebSocket)을 아우르는 풀스택 개인 프로젝트 완주
- 포트폴리오용 결과물로 활용 (취업 준비)

### 1.3 프로젝트명
**PulseGrid**

## 3. 기능 요구사항

### 3.1 수집 항목

| 우선순위 | 항목 | 비고 |
|---|---|---|
| P0 (필수) | CPU 사용률 | 전체 + 코어별(선택) |
| P0 (필수) | CPU 온도 | |
| P0 (필수) | GPU 사용률 | |
| P0 (필수) | GPU 온도 | |
| P0 (필수) | RAM 사용률 | |
| P1 (선택/확장) | 디스크 사용량 | NVMe 온도/사용률 포함 |
| P1 (선택/확장) | 배터리 잔량 | 노트북 한정 |

### 3.2 수집 주기
- **실시간 표시**: 2초 간격
- **히스토리 저장**: 1분 간격 (P1, 1차 릴리즈에서는 선택사항)

### 3.3 데이터 흐름
1. 각 기기에서 LibreHardwareMonitor 실행 (Remote Web Server 기능으로 로컬 JSON 제공)
2. Python 수집기가 JSON을 파싱하여 필요한 값만 추출
3. FastAPI 서버로 전송
4. 서버가 WebSocket으로 웹 대시보드에 실시간 전달

### 3.4 화면 요구사항
- 데스크탑/노트북 상태를 한 화면에 나란히 표시
- 주요 지표(CPU/GPU 사용률, 온도)는 실시간 그래프로 시각화
- 온도 임계치 초과 시 시각적 경고 표시 (예: 특정 온도 이상 시 색상 변경)

## 4. 비기능 요구사항

### 4.1 접근 범위
- **1차 릴리즈**: 로컬 네트워크 내 접근만 지원 (같은 공유기/와이파이 환경)
- **2차 확장 계획**: 외부 인터넷 접근 지원 (인증(Authentication) 및 HTTPS 적용 후)

### 4.2 확장성
- 새 기기 추가 시 수집기 코드 재사용 가능한 구조
- 센서 종류가 기기마다 다른 점(예: 노트북에만 배터리 존재)을 고려한 유연한 데이터 스키마

### 4.3 성능
- 히스토리 데이터 누적에 따른 저장소 부담을 고려하여 표시 주기와 저장 주기를 분리

---

## 5. 범위 외 항목 (Out of Scope, 1차 기준)
- 외부 인터넷 노출 및 인증 시스템 (2차 확장 예정)
- 모바일 전용 앱 (웹 대시보드로 우선 대응)
- 알림(푸시/메일 등) 기능

---

## 6. 마일스톤 (초안)

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| 1단계 | 로컬 JSON 파싱 | CPU/GPU/RAM 값을 Python으로 추출해 터미널 출력 |
| 2단계 | 단일 기기 실시간 연동 | FastAPI + WebSocket으로 데스크탑 1대 실시간 표시 |
| 3단계 | 다중 기기 연동 | 노트북 추가, 2대 동시 표시 |
| 4단계 | 히스토리 저장 (P1) | DB 연동, 과거 추이 그래프 |
| 5단계 | 확장 항목 (P1) | 디스크/배터리 항목 추가 |
