## 2. 컴포넌트별 역할

### 2.1 LibreHardwareMonitor (외부 도구)
- **역할**: 하드웨어 센서 값을 읽어 JSON 형태로 제공하는 "번역기"
- **동작**: Remote Web Server 기능 활성화 → `http://localhost:8085/data.json`
- **선택 이유**: Intel / AMD / NVIDIA 등 제조사가 달라도 동일한 JSON 형식으로 값을 제공하므로, 기기별 분기 처리 없이 하나의 수집기 코드로 대응 가능

### 2.2 PulseGrid Agent (Python 수집기)
- **역할**: 각 기기에서 실행되며, LibreHardwareMonitor의 JSON을 읽어 필요한 값만 추출 후 서버로 전송
- **주요 처리**
  - JSON 트리 구조를 재귀적으로 탐색해 목표 센서 값 추출
  - 기기 식별자(`device_id`) 부여
  - 기기에 없는 센서(예: 데스크탑의 배터리)는 `null` 처리
- **실행 위치**: 노트북, 데스크탑 각각 (동일 코드 재사용)

### 2.3 PulseGrid Server (FastAPI)
- **역할**: 모든 기기의 데이터를 받아 통합 관리하고, 대시보드로 실시간 전달
- **주요 처리**
  - 수집기로부터 데이터 수신 (HTTP POST)
  - 기기별 최신 상태를 메모리에 보관
  - 연결된 웹 대시보드에 WebSocket으로 브로드캐스트
  - (P1) 히스토리 데이터를 DB에 1분 간격 저장

### 2.4 웹 대시보드 (프론트엔드)
- **역할**: 사용자가 실제로 보는 화면
- **주요 처리**
  - WebSocket으로 서버에 연결하여 실시간 데이터 수신
  - 기기별 카드 형태로 지표 표시
  - Chart.js로 실시간 추이 그래프 렌더링
  - 온도 임계치 초과 시 시각적 경고 표시

## 3. 통신 방식 결정

### 3.1 수집기 ↔ 서버: Push 방식 채택

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **Push (채택)** | 수집기가 서버로 데이터를 보냄 | 서버가 각 기기의 IP를 몰라도 됨. 기기 추가가 쉬움 | 수집기가 서버 주소를 알아야 함 |
| Pull | 서버가 각 기기에 요청해서 가져옴 | 서버가 수집 주기를 일괄 통제 가능 | 서버가 모든 기기의 IP를 알아야 함. 노트북처럼 IP가 바뀌는 기기에 취약 |

**채택 근거**: 노트북은 사용 환경(집/학교)에 따라 IP가 바뀔 수 있으므로, 서버가 기기를 찾아가는 Pull 방식은 관리 부담이 큼. Push 방식은 기기가 늘어나도 서버 코드 변경이 필요 없어 확장성이 좋음.

### 3.2 서버 ↔ 대시보드: WebSocket 채택
- 브라우저가 주기적으로 요청을 반복하는 폴링 방식 대비, 서버가 값이 갱신될 때 능동적으로 밀어줄 수 있어 실시간성과 효율이 우수

## 4. 기술 스택

| 구분 | 기술 | 선택 이유 |
|---|---|---|
| 센서 수집 | LibreHardwareMonitor | 제조사 무관 통합 JSON 제공 |
| 수집기 | Python (`requests`) | 학습 중인 언어, JSON 처리 용이 |
| 백엔드 | Python / FastAPI | WebSocket 기본 지원, 문법이 간결해 학습 부담 적음 |
| 실시간 통신 | WebSocket | 서버 주도 실시간 전송 |
| 프론트엔드 | HTML + JavaScript | 초기 진입장벽 최소화 |
| 시각화 | Chart.js | 별도 빌드 없이 스크립트 삽입만으로 그래프 구현 가능 |
| DB (P1) | MariaDB | 학과 커리큘럼에서 학습 중인 DBMS |

## 5. 데이터 스키마 (개요)

기기마다 보유 센서가 다르므로, 없는 항목은 `null`로 처리하여 통일된 형식을 유지한다.

```json
{
  "device_id": "desktop",
  "device_name": "DESKTOP-5VSB06S",
  "timestamp": "2026-07-28T23:15:00",
  "cpu": { "usage": 1.4, "temp": 46.0 },
  "gpu": { "usage": 0.0, "temp": 37.7 },
  "ram": { "usage": 32.0 },
  "disk": { "usage": 44.1, "temp": 51.0 },
  "battery": null
}
```

> 상세 필드 정의 및 엔드포인트 규격은 **API 명세서(03)** 에서 다룬다.

## 6. 확장 고려사항

### 6.1 기기 추가
새 기기를 추가할 때 필요한 작업은 아래 2가지로 한정된다.
1. 해당 기기에 LibreHardwareMonitor 설치 및 Remote Web Server 활성화
2. PulseGrid Agent 실행 (설정 파일에 `device_id`와 서버 주소만 지정)

서버 및 프론트엔드 코드 수정은 불필요하도록 설계한다.

### 6.2 외부 접근 (2차 확장)
1차에서는 로컬 네트워크로 한정하되, 2차 확장 시 아래 요소를 추가한다.
- 인증(Authentication) 계층
- HTTPS 적용
- 수집기 → 서버 전송 시 API 키 등 식별 수단
