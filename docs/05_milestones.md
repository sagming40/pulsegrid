### M6.5. 시각화 확장 (히트맵 + 전력 + 테마) ✅ 완료

| 항목 | 내용 |
|---|---|
| 목표 | 대시보드 하단 여백 활용 — 누적 데이터 시각화, 내부 지표 확장, UX 디테일 보강 |
| 주요 작업 | **[A그룹 — 히스토리 히트맵]**<br>1. 시간대별 평균 집계 SQL 및 `get_heatmap()` 작성<br>2. `GET /api/v1/heatmap` 엔드포인트 구현<br>3. 프론트엔드 히트맵 렌더링<br>**[B그룹 — 전력 지표 확장]**<br>4. config.json에 CPU/GPU 전력(W) 센서 추가<br>5. models.py/agent.py 전력값 파싱<br>6. 히스토리 테이블에 전력 컬럼 추가<br>7. 프론트엔드 카드에 전력(⚡) 표시<br>**[C그룹 — 테마 설정]**<br>8. CSS 색상값 변수화(리팩터링)<br>9. `prefers-color-scheme` 기반 다크모드<br>10. 톱니바퀴 토글(시스템/라이트/다크) + localStorage 저장 |
| 기술 요소 | SQL 집계(GROUP BY / HOUR), CSS 변수 기반 테마 시스템, 색상 보간(color interpolation) |
| **완료 기준** | 대시보드 하단에 (1) 시간대별 CPU 사용률 히트맵과 (2) 기기별 실시간 소비 전력(W)이 표시되고, (3) 라이트/다크 테마를 페이지 안에서 직접 전환할 수 있음 |
| 리스크 | 범위 변경 — 원래 B그룹(외부 날씨 API)은 "왜 PC 모니터링 대시보드에 날씨가 있는가"라는 정체성 문제로 재검토, 데스크탑 카드 하단에 배터리 대응 지표가 없어 허전해 보이던 UI 문제(사용자 관찰)를 계기로 "내부 전력 지표"로 대체. 외부 API 연동이라는 원래 학습 목표는 버리지 않고 M8로 분리 |
| 확인 결과 | **A그룹**: `HOUR(recorded_at)` 기준 GROUP BY로 기기별 시간대 평균 집계, `GET /api/v1/heatmap?hours=` 구현, 프론트엔드에 기기별 24칸 그리드로 렌더링. 초기엔 반투명(rgba) 방식으로 색을 표현했으나 다크모드 배경에서 대비가 무너지는 문제 발견 → "두 색상 끝점을 직접 보간"하는 방식으로 교체. 보라 계열 색상도 명암 대비가 약해 주황/크림 계열로 재변경. 또한 고정된 0~100% 스케일 대신 실제 데이터 내 최댓값 기준으로 스케일을 재조정해 실사용 범위(5~20%대)에서도 진하기 차이가 잘 보이도록 개선<br>**B그룹**: LibreHardwareMonitor의 `Power` 타입 센서(desktop: `/amdcpu/0/power/0`, `/gpu-nvidia/0/power/0` 등) 확인 후 config.json sensor_map에 추가, models.py/agent.py에서 파싱, 히스토리 테이블에 cpu_power/gpu_power 컬럼 추가. 프론트엔드 카드 우측 하단에 CPU+GPU 합산 전력(W)과 배터리를 세로로 나란히 배치해, 데스크탑(배터리 없음)에도 의미 있는 값이 채워지도록 함<br>**C그룹**: style.css 전체 색상값을 CSS 변수로 리팩터링(기능 변화 없이 순수 리팩터링만 먼저 진행) 후, `@media (prefers-color-scheme: dark)`로 시스템 연동 다크모드 적용. 이어서 톱니바퀴 버튼 + 드롭다운(시스템/라이트/다크)으로 페이지 내 수동 전환 기능 추가, `html[data-theme]` 속성으로 시스템 설정과 무관하게 강제 적용 가능하도록 구현, `localStorage`로 선택값 유지. 테마 전환 시 히트맵도 즉시 재계산되도록 연동 |

| 목표 | 공공데이터포털 전력수급 현황 API를 연동해, PulseGrid의 "부하 모니터링"이라는 주제를 개인 PC 단위에서 국가 단위로 확장 |
| 배경 | 원래 M6.5 B그룹이었던 "외부 날씨 API 연동" 계획을 대체 — 날씨는 프로젝트 정체성과의 연관성이 약해 M6.5에서는 내부 전력 지표로 방향을 틀었고, 외부 REST API + 서버 캐싱이라는 원래 학습 목표는 이 마일스톤으로 분리해 이어감 |
| 주요 작업 | 1. 공공데이터포털 API 키 발급 및 `power_config.json` 분리(gitignore)<br>2. 서버에서 주기적 호출 + 캐싱하는 백그라운드 태스크 추가<br>3. `GET /api/v1/power-status` 엔드포인트 구현<br>4. 프론트엔드에 전국 전력수급 카드 표시 |
| 기술 요소 | 외부 REST API 연동, 서버 사이드 캐싱, API 키 관리 |
| **완료 기준** | 대시보드에 전국 전력수급 현황(공급능력/현재부하/예비율 등)이 표시되고, API는 한도 내 주기로만 호출됨 |
| 리스크 | 외부 API 키 노출 / 호출 한도 초과 → 서버 경유 호출 + 캐싱으로 대응, 키 파일은 gitignore |

## 4. 진행 순서 및 의존 관계

```
M0 ──▶ M1 ──▶ M2 ──▶ M3 ──▶ M4  ═══▶ v1.0 릴리즈 완료                          
                                │
                                ├──▶ M5 (히스토리)
                                ├──▶ M6 (확장 지표)
                                ├──▶ M6.5 (시각화 확장)
                                ├──▶ M7 (문서화)
                                └──▶ M8 (전국 전력수급, M7 이후 진행)
```

- M1 ~ M4는 **순차 진행 필수** (앞 단계 없이 다음 단계 불가)
- M5 ~ M7은 v1.0 이후 **독립적으로 진행 가능** (순서 자유)

## 6. 완료 정의 (Definition of Done)

각 마일스톤은 아래 조건을 **모두** 충족해야 완료로 간주한다.

1. 해당 단계의 완료 기준이 실제로 동작함
2. 코드가 Git에 커밋되어 있음
3. 다음 단계를 진행할 수 있는 상태로 정리됨 (임시 코드 제거)
